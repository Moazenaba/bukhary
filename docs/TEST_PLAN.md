# خطة الاختبار — مسابقات مسجد الإمام البخاري

الهدف: نلاقي الأخطاء **قبل** ما توصل للناس. كل طلب دمج (Pull Request) وكل دفعة على `main` بتعدّي
على كل الاختبارات دي في GitHub Actions، ولو اختبار واحد فشل التغيير ما يتقبلش.

## إزاي فكّرنا فيها

بدأنا من سؤال: **إيه اللي ممكن يبوظ، وأغلى خطأ فيهم إيه؟** وبعدين حطينا كل خطر في المستوى اللي
يمسكه بأرخص وأسرع شكل.

| الخطر | مثال حقيقي | المستوى اللي يمسكه |
|---|---|---|
| حد ياخد صلاحية مش بتاعته | شيخ يعدل لجنة مش لجنته، رئيس لجنة يشوف امتحان مش متحدد له | Unit (مصفوفة الصلاحيات) + Integration (مصفوفة على الـ API) + Security (كل مسار محمي) |
| مراحل اللجنة تبقى غير منطقية | «تم الحفل» والامتحان ما اتعملش، أو حفل يتسجل قبل ميعاده | Unit + Property (آلاف التسلسلات العشوائية) + Integration |
| البيانات تختلف بين مكانين | مهمة الحفل في التقويم «تمت» واللجنة «لم يتم الحفل» | Integration |
| حذف يسيب روابط بايظة | لجنة اتمسحت وفضلت مسندة لشيخ فحفظه يفشل | Integration |
| تعديل قاعدة البيانات يمسح أو يبوظ بيانات | migration اتعدلت بعد ما اتطبقت، أو تشغيلها مرتين يكرر حاجة | Migration |
| الشاشة تعرض حاجة غلط | مكان الشيخ ما يظهرش، فلتر «لم يتم الحفل» يعد غلط، تعديل يتبعت مع كل حرف | Component |
| تسلسل كامل يبوظ في المتصفح | تسجيل الدخول ← لجنة ← الكشف ← الحفل ← PDF | E2E (متصفح حقيقي، كمبيوتر وموبايل) |
| الموقع والتطبيق يختلفوا في شكل الطلبات | التطبيق يبعت حقل اسمه غلط | Contract |
| ملف PDF/Excel بايظ | ملف ما يفتحش أو عربي مقطع | Unit (بنية الملف) + E2E (تنزيل حقيقي) |
| أسرار تترفع على GitHub | كلمة سر قاعدة بيانات أو مفتاح | CI (فحص الأسرار) + Dependency audit |

## المستويات

### 1. Unit — منطق خالص بدون قاعدة بيانات (`tests/unit/`)
- **مصفوفة الصلاحيات** (`policy-matrix`): جدول صريح لكل دور × كل إجراء. أي تغيير في الصلاحيات لازم
  يتكتب في الجدول عن قصد، وإلا الاختبار يفشل.
- **قواعد المراحل — Property-based** (`workflow-properties`): آلاف التسلسلات العشوائية من «إكمال/إلغاء»
  المراحل؛ لازم دايماً المراحل المكتملة تكون متتالية من الأول، وما فيش حفل يتسجل قبل ميعاده.
- **حالة اللجنة الحالية** (`stage-utils`): كل التوافيق الممكنة لمراحل اللجنة (512 حالة) بتدّي حالة واحدة
  منطقية متوافقة مع فلاتر الشاشات.
- **دمج الكشف مع اللجان** (`committee-sync`): بيانات اللجنة هي المرجع، المكان من «مكان الشيخ»، ولا حاجة تتمسح.
- **ملف PDF** (`pdf-writer`): الملف اللي بيتعمل بنيته سليمة (الجدول المرجعي xref بيشاور على المكان الصح).
- **التحقق من المدخلات** (`schemas`): أرقام التليفون العربي والإنجليزي، التواريخ الغلط.

### 2. Component — الشاشات في متصفح وهمي (`tests/component/`)
- كشف الدورة: مكان الشيخ يظهر، الفلاتر تعد صح، التعديل يتحفظ مرة واحدة عند الخروج من الخانة، و Esc يلغي.
- إضافة لجنة: كل «مرحلة بداية» بتنتج مراحل من غير فجوات.
- شريط الموبايل: زرار «+ لجنة» يظهر بس للي يقدر يضيف.
- الحفلات: أزرار PDF مقفولة لما مفيش حفلات.

### 3. Integration — الـ API مع PostgreSQL حقيقي (`tests/*.test.ts`, `tests/integration/`)
- **مصفوفة الصلاحيات على الـ API**: كل دور يجرب كل نوع طلب، والنتيجة لازم تطابق قواعد الصلاحيات.
- **كل مسار محمي**: أي مسار جديد في الـ API من غير تسجيل دخول لازم يرجع 401 (إلا قائمة صغيرة معروفة).
- قواعد المراحل، الحفل ومهمته، الحذف والروابط، المستخدمين، الامتحانات، الجلسات (موجودة ومتوسعة).

### 4. Migration — تعديلات قاعدة البيانات (`tests/migrations*.test.ts`)
- من قاعدة قديمة ومن قاعدة فاضية: كل الـ migrations تتطبق.
- **قفل الـ migrations**: أي ملف migration اتطبق قبل كده ما يتعدلش (البصمة متسجلة)؛ التعديل يكون بملف جديد.
- الترقيم متتالي ومن غير تكرار.
- تشغيلها مرتين ما يغيرش ولا يمسح أي بيانات.
- العلاقات والقيود المهمة موجودة فعلاً في قاعدة البيانات (رقم اللجنة مش متكرر في نفس الدورة، الدورة
  ما تتمسحش ولها لجان...).

### 5. Contract — الموقع والتطبيق (`tests/contract/`)
- الطلبات اللي التطبيق بيبعتها لازم السيرفر يقبلها (موجود).

### 6. E2E — متصفح حقيقي (`tests/e2e/`)
- على مقاس كمبيوتر وموبايل: تسجيل الدخول، إضافة دورة ولجنة، الكشف بيعرض المكان ويعدّل اللجنة، الحفلات
  وتصدير PDF حقيقي، ومفيش صفحة بتخرج عن عرض الموبايل، ومفيش أخطاء في الـ console.

### 7. CI — البوابة (`.github/workflows/ci.yml`)
- فحص الأسرار، Type check، كل اختبارات Unit/Component/Integration/Migration/Contract، البناء، E2E،
  وفحص ثغرات المكتبات. التطبيق (Android) له CI في مستودعه: اختبارات الوحدة والبناء.

## التشغيل محلياً
```bash
npm test                 # Unit + Component + Integration + Migration + Contract (يحتاج PostgreSQL)
npm run test:unit        # المنطق الخالص والشاشات فقط، من غير قاعدة بيانات
npm run test:e2e         # المتصفح (السيرفر شغال على localhost:3000 وفيه حساب الاختبار)
```

## قفل الدمج على GitHub
علشان «ما يتقبلش أي حاجة غير لما تعدّي»: من إعدادات المستودع ← Branches ← Add rule لـ `main`:
- Require a pull request before merging
- Require status checks to pass: اختار **Type check, tests, build** و **E2E (browser)** و **Dependency audit**
- Do not allow bypassing the above settings
