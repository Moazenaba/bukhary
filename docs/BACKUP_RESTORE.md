# النسخ الاحتياطي والاسترجاع

الهدف: لو أي بيانات باظت أو اتمسحت، نرجّعها كاملة. النسخة اللي بنعملها هنا **شاملة لكل حاجة حرفياً**:
كل الجداول (اللجان، الدورات، المستخدمين وكلمات السر المشفرة، المهام، الحفلات، الكشوفات، الدرجات،
الإشعارات، سجل التعديلات، الصلاحيات) **وملفات الامتحانات PDF نفسها** (متخزنة جوه قاعدة البيانات)،
وجدول نسخ قاعدة البيانات (schema_migrations).

> اتجرّبت: نسخة من قاعدة فيها 1,500 لجنة و1,000 مستخدم و5,000 مهمة وملف امتحان PDF، واسترجاعها في
> قاعدة فاضية ← **كل الـ 22 جدول رجعوا متطابقين** (نفس عدد الصفوف ونفس المحتوى)، وملف الـ PDF رجع
> **نفس البايتات بالظبط**.

## ⚠️ قبل أي حاجة
- النسخة فيها بيانات الناس وكلمات السر (مشفّرة). **ما تتبعتش على واتساب، وما تترفعش على GitHub**
  (فولدر `backups/` متجاهل في git).
- خزّنها **مشفّرة** (مثلاً ملف 7-Zip بكلمة سر قوية، أو قرص مشفّر)، وخلّي منها **3 نسخ في مكانين
  مختلفين على الأقل** (جهازك + هارد خارجي/درايف مشفّر).
- اعمل نسخة **قبل** أي حاجة كبيرة: قبل أي deploy فيه migration، قبل استيراد كشف كامل، قبل مسح دورة.

## الطريقة 0 (فوري، من غير أي برامج): من SQL Editor بتاع Supabase
الملفات في [`docs/sql/`](sql/). في Supabase ← **SQL Editor** ← New query ← الصق الملف كله ← **Run**:

| الملف | بيعمل إيه |
|---|---|
| [`1_backup_now.sql`](sql/1_backup_now.sql) | نسخة كاملة فورية: كل الجداول بكل الصفوف وملفات الـ PDF، في مكان منفصل جوه القاعدة اسمه `backup_<التاريخ>_<الساعة>`. بيعرض عدد صفوف كل جدول في الأصل وفي النسخة (لازم يتساووا). ما بيغيّرش أي حاجة في البيانات. |
| [`2_list_backups.sql`](sql/2_list_backups.sql) | النسخ الموجودة ووقتها وحجمها. |
| [`3_restore.sql`](sql/3_restore.sql) | استرجاع كامل من نسخة (اكتب اسمها في أول سطر). **قبلها بيحفظ الوضع الحالي** في `before_restore_<الوقت>`، و**كله أو ولا حاجة**: لو أي خطوة فشلت ما بيتغيرش شيء. |
| [`4_delete_old_backup.sql`](sql/4_delete_old_backup.sql) | مسح نسخة قديمة لتوفير المساحة. |

> اتجرّب: نسخة ← تخريب البيانات (مسح نص اللجان، تغيير أسماء كل المستخدمين، مسح ملفات الامتحانات
> والمهام) ← استرجاع ⇒ **كل الجداول رجعت مطابقة تماماً** لما قبل التخريب، وملف الـ PDF نفس البايتات.
> والموقع والـ API العام ما يقدروش يقروا النسخة.

⚠️ النسخة دي **جوه نفس قاعدة البيانات**: بتحمي من أي بيانات تتمسح أو تبوظ بالغلط، لكن لو المشروع
نفسه على Supabase ضاع، بتضيع معاه. علشان كده خليها مع الطريقة 2 أو النسخة الليلية على GitHub.
وكل نسخة بتاخد مساحة قد البيانات (الخطة المجانية 500 ميجا) — امسح القديم بـ `4_delete_old_backup.sql`.

## الطريقة 1 (الأسهل): من لوحة Supabase
1. ادخل Supabase ← مشروعك ← **Database ← Backups**.
2. لو الخطة مدفوعة: فيه نسخ يومية تلقائية، وتقدر تعمل **Restore** لأي يوم منها من نفس الصفحة.
3. للنسخة المجانية: النسخ التلقائية محدودة، فاستخدم الطريقة 2 كمان.

## الطريقة 2 (النسخة الكاملة الأساسية): `npm run backup` من جهازك
بتطلّع ملف `.dump` واحد فيه كل حاجة، وده اللي بنرجّع منه.

**مرة واحدة بس:**
1. نزّل أدوات PostgreSQL **إصدار 17 أو أحدث** (Supabase بيحتاج 17):
   من https://www.postgresql.org/download/windows/ ← في التثبيت اختار **Command Line Tools** بس.
2. في فولدر المشروع، ملف `.env` فيه `DATABASE_URL` بتاع Supabase (من Supabase ← Project Settings ←
   Database ← Connection string ← URI)، و`DATABASE_CA_CERT_PATH` لشهادة Supabase.
3. لو `pg_dump` مش معروف في الـ PATH، حط مكانه في `.env`:
   `PG_DUMP=C:\Program Files\PostgreSQL\17\bin\pg_dump.exe`

**كل مرة تعمل نسخة:**
```bash
npm run backup -- --remote
```
هيكتب: `Backup written: backups\bukhari-2026-....dump (… KB)`. انقل الملف لمكان آمن مشفّر.

## الطريقة 2-ب (تلقائي كل ليلة): النسخة الليلية على GitHub
كل ليلة الساعة 1:17 بتوقيت القاهرة، GitHub بيعمل لوحده:
1. نسخة كاملة من قاعدة البيانات الحقيقية (`bukhari.dump`) + **نسخة CSV من كل جدول** بتتفتح في Excel
   بالعربي + ملف بعدد الصفوف في كل جدول (`counts.txt`).
2. **بيرجّع النسخة في قاعدة فاضية ويقارن كل جدول** — لو أي حاجة مختلفة، التشغيل بيفشل وبيوصلك إيميل.
3. بيقفل الملف بكلمة السر بتاعتك (تشفير AES-256) ويحفظه **90 يوم**.

### الإعداد (مرة واحدة)
في GitHub: المستودع ← **Settings ← Secrets and variables ← Actions ← New repository secret**، اعمل اتنين:
| الاسم | القيمة |
|---|---|
| `PROD_DATABASE_URL` | رابط قاعدة البيانات من Supabase: Project Settings ← Database ← Connection string ← **Session pooler** ← URI (فيه كلمة سر القاعدة) |
| `BACKUP_PASSPHRASE` | كلمة سر قوية **12 حرف على الأقل** تقفل بيها النسخ. **احفظها في مكان آمن**: من غيرها النسخ ما تتفتحش، ومحدش (ولا GitHub ولا أنا) يقدر يرجّعها |

بعدها جرّبها فوراً: **Actions ← Nightly database backup ← Run workflow**، ولما تخلص (✓ خضرا) هتلاقي
الملف تحت **Artifacts** في صفحة التشغيل.

### فتح النسخة واسترجاعها
1. نزّل الملف من Actions ← التشغيل ← Artifacts (ملف zip جواه `bukhari-backup-….tar.gpg`).
2. افتحه بكلمة السر (على ويندوز: Gpg4win، أو Git Bash):
   ```bash
   gpg --decrypt bukhari-backup-....tar.gpg > backup.tar
   tar -xf backup.tar
   ```
   هيطلع: `bukhari.dump` (للاسترجاع الكامل) و`csv/` (كل جدول في ملف Excel) و`counts.txt`.
3. للاسترجاع الكامل: اتبع «الاسترجاع» تحت بملف `bukhari.dump`. أو ابعتلي اسم النسخة واللي باظ وأنا
   أكتبلك الخطوات بالظبط.

## الطريقة 3: زرار «نسخة احتياطية» في الموقع (للأدمن)
بينزّل ملف `.db` (SQLite) فيه كل الجداول — مفيد إنك **تفتح البيانات وتقراها** (مثلاً ببرنامج
DB Browser for SQLite) أو ترجّع بيانات لجنة واحدة يدوياً. **مش** هو الملف اللي بنعمل منه استرجاع
كامل للسيرفر؛ للاسترجاع الكامل استخدم ملف الطريقة 2.

## الاسترجاع (لو البيانات باظت)

**القاعدة الذهبية: ما ترجّعش فوق قاعدة البيانات الشغالة مباشرة.** رجّع الأول في قاعدة جديدة، اتأكد
إنها سليمة، وبعدين بدّل.

### أ) استرجاع كامل
1. **وقّف التعديلات**: اعمل نسخة من الوضع الحالي البايظ برضه (`npm run backup -- --remote`) — لو
   احتجنا منه حاجة.
2. اعمل قاعدة جديدة فاضية (مشروع Supabase جديد، أو قاعدة جديدة في نفس السيرفر).
3. رجّع النسخة فيها:
   ```bash
   pg_restore --no-owner --no-privileges --dbname="<رابط القاعدة الجديدة>" backups\bukhari-....dump
   ```
4. **اتأكد** (الخطوة الجاية) إن الأعداد منطقية.
5. غيّر `DATABASE_URL` في إعدادات السيرفر (Vercel ← Settings ← Environment Variables) للقاعدة الجديدة
   واعمل Redeploy. لو النسخة أقدم من الكود الحالي، شغّل `npm run migrate:prod` بعدها (بيكمّل أي
   migration ناقصة من غير ما يمسح حاجة).

### ب) استرجاع جدول واحد أو بيانات لجنة واحدة
رجّع النسخة كلها في قاعدة **مؤقتة** (زي أ-2 و أ-3)، وبعدين انسخ منها اللي محتاجه بس. ابعتلي وأنا
أكتبلك الأمر بالظبط حسب اللي باظ.

### التأكد إن النسخة سليمة
بعد أي استرجاع، شغّل على القاعدة اللي رجعت:
```sql
SELECT relname AS "الجدول", n_live_tup AS "تقريباً عدد الصفوف"
FROM pg_stat_user_tables ORDER BY relname;
```
وقارن عدد اللجان والمستخدمين والمهام بالأرقام اللي تعرفها. وجرّب: تسجيل دخول، فتح لجنة، تنزيل ملف
امتحان.
